# Install:
#   uv venv --python 3.12
#   uv pip install torch==2.10.0+cu128 torchvision==0.25.0+cu128 \
#       --index-url https://download.pytorch.org/whl/cu128
#   uv pip install -r requirements.txt
#
# Install the torch wheels first: they carry a +cu128 local version and are
# published only on the PyTorch index, and uv resolves each package from the
# first index that publishes it (that index also serves a stale `requests`,
# which makes a single combined install unsatisfiable).
#
# Three items here are load-bearing -- do not "upgrade" them casually:
#
#   lerobot==0.6.0  Must stay >=0.6.0. Upstream scaled pi0's image and language
#                   embeddings by sqrt(hidden_size) between 2026-02-23 and
#                   2026-05-05, and the PyPI 0.5.0 release sits inside that
#                   window. The checkpoints in models/ were trained without the
#                   scaling, so serving them on 0.5.0 collapses every predicted
#                   action onto the dataset mean (the robot lunges to one fixed
#                   pose). The version string alone does not tell you which you
#                   have -- upstream main kept reporting "0.5.0" for months
#                   after the fix. Check the code:
#                     grep "pooler_output \*" \
#                       .venv/lib/python*/site-packages/lerobot/policies/pi0/modeling_pi0.py
#                   A match means you have the broken build.
#
#   lerobot patch   The wheel alone is NOT enough to serve an rtc-train
#                   checkpoint (models/*-rtctrain-*). Stock 0.6.0 has no
#                   train-time RTC: PI0Config/PI05Config lack the rtc_train_*
#                   fields, so loading such a checkpoint logs "Dropping
#                   config.json keys not defined on PI0Config" and
#                   server.py::_configure_rtc_train then fails the --rtc-train
#                   guard. Apply the same patch the checkpoints were trained
#                   with, and re-apply after every lerobot (re)install --
#                   pip/uv restore the pristine wheel and revert it silently:
#                     bash scripts/apply_lerobot_rtc_train_patch.sh
#                   Check the code:
#                     grep rtc_train_enabled \
#                       .venv/lib/python*/site-packages/lerobot/policies/pi0/configuration_pi0.py
#                   No match means the patch is missing.
#
#   torchcodec      Must be the plain PyPI build, NOT 0.10.0+cu128. The cu128
#                   build cannot load its FFmpeg shared libraries, which breaks
#                   LeRobotDataset video decoding.
